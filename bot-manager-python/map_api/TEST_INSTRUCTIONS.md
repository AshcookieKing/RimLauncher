# Инструкция по тестированию координат

## Подготовка

### 1. Остановить Arma 3 сервер
```cmd
taskkill /F /IM arma3server_x64.exe
```

### 2. Очистить очередь спавна (опционально)
Через MySQL клиент или phpMySQL:
```sql
USE arma3_slserver;
DELETE FROM arma_map_zone_spawn_queue WHERE server_id = 1;
```

## Тестирование

### Вариант 1: Через веб-интерфейс

1. **Запустить map_api**
   ```cmd
   cd C:\rim_online_bot\bot-manager-python\map_api
   run_map_api.cmd
   ```

2. **Открыть веб-карту**
   - URL: http://localhost:5000/
   - Если требуется Write Key - ввести в поле

3. **Спавн тестового аванпоста**
   - Выбрать "Операции карты" → "Активности"
   - Выбрать "Что спавнить" → "Аванпост"
   - Кликнуть **точно по центру карты**
   - Проверить статус: должно быть "Аванпост в очереди"

4. **Проверить логи Python**
   В консоли map_api должна появиться строка:
   ```
   [SPAWN_REQUEST] template=avanpost_1, coords: X=10250.0, Y=0.0, Z=10250.0
   ```
   
   **Ожидаемые значения для центра карты:**
   - X ≈ 10250 (восток)
   - Y = 0 (высота)
   - Z ≈ 10250 (север)

5. **Запустить Arma 3 сервер**
   ```cmd
   cd C:\a3server
   START.bat
   ```

6. **Проверить логи Arma 3**
   Открыть: `C:\a3server\mpmissions\Rim_Conflict_base.Kapaulio\arma3server_*.rpt`
   
   Искать строки:
   ```
   [RIM_mapZoneSpawn] trigDB=[10250,0,10250] trigATL=[10250,XXX,10250] id=...
   [RIM_mapZoneSpawn] OK id=... zone_uid=... pos=[10250,0,10250]
   ```
   
   **Проверить:**
   - `trigDB` должен быть `[10250, 0, 10250]`
   - `trigATL` должен быть `[10250, высота_рельефа, 10250]`
   - Высота рельефа обычно 50-150 метров

7. **Проверить в игре**
   - Подключиться к серверу
   - Открыть карту (M)
   - Найти маркер зоны - должен быть **в центре карты**
   - Телепортироваться: `player setPosATL [10250, 0, 10250]`
   - Проверить что аванпост:
     - ✓ На правильном месте (центр карты)
     - ✓ На земле (не в воздухе)
     - ✓ Не внизу карты

## Диагностика проблем

### Проблема: Аванпост внизу карты (Z ≈ 0)

**Симптомы:**
- В логе Python: `Z=0.0` или малое число
- В логе Arma: `trigDB=[X,Y,0]`
- На карте: маркер в юго-западном углу

**Причина:** JavaScript неправильно вычисляет `pos_z`

**Решение:**
1. Проверить функцию `latLngToArma` в `templates/map.html`
2. Проверить что используется правильный режим (с тайлами или без)

### Проблема: Аванпост в воздухе (Y >> 0)

**Симптомы:**
- В логе Python: `Y=10250.0` (большое число)
- В логе Arma: `trigDB=[X,10250,Z]`
- В игре: композиция высоко в воздухе

**Причина:** Координаты Y и Z перепутаны

**Решение:**
1. Проверить что JavaScript отправляет правильные координаты
2. Проверить что Python API не меняет координаты местами

### Проблема: Аванпост только по оси X

**Симптомы:**
- В логе: `Z=0` всегда
- Маркер всегда на линии X

**Причина:** `latLngToArma` возвращает `pos_z = 0`

**Решение:**
1. Проверить режим карты (TILE_MODE)
2. Проверить формулу: `pos_z = ll.lat` (с тайлами) или `pos_z = MAP_SIZE - ll.lat` (без тайлов)

## Дополнительная проверка

### Проверить пропы (объекты)
Пропы должны отображаться правильно на карте. Если пропы правильные, а зоны нет - проблема в коде спавна зон.

```sql
SELECT classname, pos_x, pos_y, pos_z
FROM arma_map_objects
WHERE server_id = 1
LIMIT 5;
```

Проверить что:
- `pos_x` = восток (0-20500)
- `pos_y` = высота (обычно 0-500)
- `pos_z` = север (0-20500)

### Проверить маркеры
```sql
SELECT marker_name, pos_x, pos_y, pos_z
FROM arma_map_markers
WHERE server_id = 1
ORDER BY updated_at DESC
LIMIT 5;
```

Маркеры должны иметь правильные координаты.
