ПРОБЛЕМА НАЙДЕНА И ИСПРАВЛЕНА!
--------------------------------

В JavaScript функции xzFromMapLiveEntity() и xzHorizontalFromDbRow() 
использовали эвристику которая пыталась "угадать" где север - в pos_y 
или в pos_z. Это ломало координаты для объектов на земле.

ЧТО ИСПРАВЛЕНО:
---------------

1. templates/map.html - функция xzFromMapLiveEntity():
   Теперь просто возвращает { x: pos_x, z: pos_z }
   БЕЗ эвристики которая путала Y и Z

2. templates/map.html - функция xzHorizontalFromDbRow():
   Теперь просто возвращает { x: pos_x, z: pos_z }
   БЕЗ сложной логики с проверками

РЕЗУЛЬТАТ:
----------

✅ Игроки будут отображаться правильно
✅ Техника будет отображаться правильно  
✅ NPC будут отображаться правильно
✅ Объекты будут отображаться правильно
✅ NPC больше не будут "плыть" вниз

КАК ПРОТЕСТИРОВАТЬ:
-------------------

1. Перезапустите map_api:
   - Остановите текущий процесс (Ctrl+C)
   - Запустите заново: run_map_api.cmd

2. Откройте веб-карту: http://localhost:5050/map

3. Проверьте что:
   - Техника показывается в правильных местах (не внизу карты)
   - NPC показываются в правильных местах
   - Объекты показываются в правильных местах
   - Игрок показывается правильно при заходе

4. Подождите 30-60 секунд и проверьте что NPC не "плывут" вниз

ТЕХНИЧЕСКИЕ ДЕТАЛИ:
-------------------

Координаты в БД правильные:
- pos_x = восток (east)
- pos_y = высота (height/AGL)
- pos_z = север (north)

Проблема была только в JavaScript отображении!

Старая логика пыталась определить:
- Если pos_z маленькое (< 0.5) и pos_y большое (> 200)
  → думала что север в pos_y
- Это ломало координаты для объектов на земле

Новая логика:
- Всегда использует pos_x как восток, pos_z как север
- Никаких эвристик и угадываний!
